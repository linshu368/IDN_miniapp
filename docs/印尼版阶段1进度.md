## 4. 部署方式和中文版的差别

产品拓扑一样：Telegram Mini App → Vercel 前端 → Railway API → Supabase。

发布流水线**还不一样**：

| | 中文现网 | 印尼现在 |
|---|---|---|
| 前端 | Vercel Git 跟分支自动发 | Git 已接上，但**生产分支是 `main`**；`main` 仍 `856329d`（远端已确认），隔离提交只在 `dev` `c3b12b7`。当前线上包是本地 `dev` 的 `vercel --prod` |
| 后端 | GitHub → Railway 自动构建 | Railway GitHub App **看不到**私有仓，报 `Repository not found or is not accessible`。当前线上是本地 `railway up` + `railway redeploy` |
| Railway 服务 | `stminiapp` + 支付 Worker + Cron | 只有 `backend`；无支付进程 |
| PR 临时环境 | `railway-pr-env.yml` | 已改成 `workflow_dispatch`，避免误用中文 Railway 项目 ID |

要对齐中文那套「push 即发布」，需要：

1. 在 Railway GitHub App 里授权 `linshu368/IDN_miniapp`；
2. 把 `c3b12b7` 推到 `main`，或把 Vercel 生产分支改成 `dev`；
3. 提交根目录 `Dockerfile` / `.dockerignore`（见 §8）。

在那之前请继续用 CLI 发，不要假设 push `main` 会更新印尼前端。

补充两点（本轮实测）：

- `railway redeploy --service backend -y` **能用**，它重放当前镜像并注入最新变量，不依赖 GitHub 源。改完变量用它重启即可，不必 `railway up` 重建。

直连  db.<project-ref>.supabase.co:5432（导入结构时用的，可用）

`.local-idn/bootstrap.env` 和 Railway 控制台里的 `DATABASE_URL` / `TEST_DATABASE_URL` **已经是 aws-0**。  
`CHAT_HISTORY_SYNC_ENABLED`、`LOBBY_RANKING_REFRESH_ENABLED` 已改回 `true`。
