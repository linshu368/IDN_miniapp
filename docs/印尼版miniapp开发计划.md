# 印尼版 MiniApp 开发计划

> 上游决策：`docs/印尼版miniapp开发思路.md`。本计划只覆盖独立印尼副本，不改中文仓库。
>
> 开发口令：**copy 独立副本 → mock 明确不做的入口 → 印尼语适配与内容入库 → 真机验收上线。**

---

## 0. 交付定义（DoD）

用印尼 Telegram 账号在真机 Mini App 走通：

1. 印尼 Bot 的名称、`/start`、菜单按钮和 Mini App 界面均为印尼语。
2. 大厅只展示已适配的印尼语角色卡；详情与开场白为印尼语。
3. 发消息流式回复为印尼语；可重生成；可切模型 / 生成偏好。
4. 每日签到能领星尘；无充值时，新用户、免费额度、签到和邀请奖励足够支持基本体验。
5. 邀请中心可复制专属链接；新账号经 `?startapp=inv_` 绑定；邀请人获得已配置的注册和/或聊天轮次奖励；首次付费奖励关闭。
6. 消息中心有至少一条印尼语官方公告；用户可留言客服，印尼 CS 后台可查看和回复。
7. 创作/许愿、充值/订单、语音均为 mock：页面直接访问、底部 Tab、聊天工具箱及所有余额不足分支均不触发真实支付、许愿写入或 TTS。
8. 独立的 Bot、Vercel、Railway、Supabase、Admin、CS 均指向印尼环境；中文现网未被改动。

未适配完成的卡必须设为 `enabled=false`；印尼大厅不允许出现中文卡。

## 1. 工期与并行关系

按 **1 名熟悉本仓库的全职工程师 + 内容/运营并行** 估算：

| 工作包 | 人日 | 说明 |
| --- | --- | --- |
| A. 副本与隔离基建 | 4–6 | 基线 tag/新仓库、Supabase 结构基线、Bot、Railway API、Vercel、Admin/CS |
| B. mock 不做的能力 | 1–2 | 充值、许愿、语音、路由直访和全部 402 分支；不删后端模块 |
| C. C 端与用户可见 API 印尼语 | 5–8 | 硬编码、错误/状态、时间、`lang`、Bot 文案与扫漏 |
| D. 印尼 runtime config 与星尘策略 | 1–2 | 配置包导入、无充值策略、邀请规则；正文由内容方提供 |
| E. 角色卡与 Storage | 1–2 | 资源导入和启用控制；翻译/校对另计 |
| F. 联调、双账号邀请、真机和生产切流 | 3–5 | Telegram WebView、SSE、CORS、回归和上线 buffer |

**工程合计：15–25 人日。** 以首发的一小批已适配角色卡为目标，建议日历按 **3–4 周**排期；空库结构、Bot/域名审批或内容延迟时按 5–6 周预留。

执行上不是纯串行：

```text
阶段 1 隔离骨架 ─┬─→ 阶段 2 mock 入口 ─┐
                 ├─→ 阶段 3 印尼语适配 ─┼─→ 阶段 5 真机验收与上线
                 └─→ 阶段 4 内容与配置 ─┘
```

内容方应从第一天开始准备首发卡、平台规则、海报与公告；内容未齐不进入投流。

## 3. 分阶段执行计划

### 阶段 1 · 隔离骨架

目标：印尼环境健康可用，且不可能误连中文环境。

1. 从中文 `dev` 创建只读基线 tag（例如 `id-fork-baseline`），据此创建新 GitHub 仓库。
2. 新建 Supabase project：
   - 从中文环境导出表、RPC、extension、grant 等**结构基线**，以空数据建库。
   - 不从迁移目录的 `001` 重放；不迁用户、订单、会话、钱包流水。
   - 验证鉴权、钱包、角色、邀请、客服、消息所需 RPC、权限和 bucket 均存在。
3. 新建印尼 Telegram Bot 与 Mini App：
   - 配置印尼 Mini App URL、`TELEGRAM_BOT_TOKEN`、`FRONTEND_URL`、`NEXT_PUBLIC_API_URL`、CORS。
   - 将 Bot 名称、`/start`、菜单按钮、命令和隐私政策链接换为印尼语。
4. 新建 Vercel（C 端）、Railway（仅 API）、Vercel Admin、Vercel CS 的独立部署。
5. 设定 `PAYMENT_ENABLED=false`；不部署支付对账 Worker 和订单过期 Cron。
6. 验收：印尼 Bot 可打开 Mini App，`X-Init-Data` 鉴权、健康检查与最小角色查询成功；所有服务的日志/监控使用独立环境标识。

### 阶段 2 · mock 明确不做的入口

目标：用户和直接 URL 均无法走入真实支付、许愿或 TTS 链路；保留引擎实现供后续启用。

| 入口 / 场景 | 副本改动与验收 |
| --- | --- |
| 创作 Tab、`/create`、`/create/wish` | 默认保留第四 Tab，落到印尼语占位页；不调用 `/api/wishes`，不写入许愿数据 |
| 「我的」充值与订单 | 入口占位或禁用；`/profile/recharge*`、订单页被直接访问时也不创建订单 |
| 聊天发送 / 重生成余额不足 | 改为页内印尼语提示，可引导签到/邀请；禁止跳 `/profile/recharge` |
| 模型切换余额不足 | 同上，覆盖 `INSUFFICIENT_CREDITS` 分支 |
| 语音气泡 / 语音设置 / 自定义台词 | 按钮 mock 或占位；不调用 voice API，余额不足也不跳充值 |
| 图片设置 | 沿用现有占位态 |
| 支付回跳 | 无真实订单时安全忽略，不恢复支付流程 |

验收：从四个 Tab、个人页、聊天工具箱、语音页以及手输 URL 逐一验证；日志中无 ZQPay 下单、`/api/wishes` 写入、MiniMax 调用或支付订单创建。

### 阶段 3 · 印尼语适配

目标：所有 C 端用户可见内容是印尼语；运营台和 CS 工作台 UI 保持中文。

| 表面 | 核对内容 |
| --- | --- |
| 根壳与导航 | `layout.tsx`、`global-error.tsx` 的 `lang="id"`；底部导航、页面标题、空态、Toast |
| 大厅与角色详情 | 卡片、搜索、筛选、详情、收藏、开场白、下架/错误状态 |
| 聊天 | 输入、SSE 错误、重生成、会话、模型/生成偏好、免费额度、mock 提示 |
| 我的与引流 | 资料、签到、钱包、邀请、消费明细、客服、消息中心 |
| 时间与格式 | 印尼语相对时间、日期/数字/币值；展示时间按 `Asia/Jakarta`；角色名截断不使用中文 7 字符规则 |
| 用户可见 API | `fail()`、会话错误、`status_label`、通知、支付/额度提示 |
| Telegram Bot | `/start`、菜单、命令、按钮、隐私政策及外部链接文案 |

不翻译注释、Admin UI 或 CS UI。完成后全文扫中文残留，并以真机流程复核。

### 阶段 4 · 内容、配置与资源入库

目标：印尼用户进入的是可聊、可持续使用的内容与经济配置。

1. 角色卡：
   - 适配 `name`、`description`、标签、开场白、`creator_notes`、`system_prompt`。
   - 上传资源至印尼 Storage，或验证复用 URL；适配完成前保持 `enabled=false`。
2. 发布印尼 `runtime_config`：
   - `system_instructions`、`interaction_mode_blocks`、`pref_word_count_tiers`：印尼语；篇幅按 kata 配置；去除「仅使用简体中文」。
   - `llm_model_catalog`、`llm_pricing_config`：保证存在可用的免费/低成本模型。
   - `miniapp_new_user_signup_bonus_credits`、`miniapp_character_free_chat_quota_limit`、`miniapp_daily_checkin_bonus_credits`：共同实现 C5 的无充值策略。
   - `miniapp_free_quota_exhausted_dialog_config`、`insufficient_credits_notice`：印尼语，且不引导充值。
   - `miniapp_invite_entry_enabled`、`miniapp_invite_reward_rules`、`miniapp_invite_center_config`：开启注册与聊天轮次奖励，关闭首次付费奖励；配置印尼语 `{link}` 模板和海报。
   - `lobby_pinned_characters`：只钉已适配且启用的角色。
3. 发布至少一条印尼语官方公告，并配置印尼语客服开场白/自动回复。
4. 移除或改写邀请页中与实际规则不一致的固定奖励数字，尤其是「2200 星尘」。

验收：新用户、免费额度耗尽、签到、邀请注册奖励、邀请聊天轮次奖励和余额耗尽都能走通；模型始终以印尼语回复。

### 阶段 5 · 真机验收、生产与投流

1. 在测试环境按 §6 逐条验收，至少使用邀请双方两个真实 Telegram 账号。
2. 修复真机特有问题：Telegram WebView、`X-Init-Data`、SSE、CORS、深链、Storage 资源加载。
3. 生产 Supabase 重复结构基线、配置包、首发角色和资源导入；生产服务使用独立 Sentry/environment。
4. 上线后重点观察：Mini App 打开率、进房率、首轮回复语言、SSE 成功率、邀请绑定/发奖、免费额度与余额耗尽后的 mock 提示。

## 4. 真机验收清单

- [ ] 印尼 Bot、`/start`、菜单和隐私政策链接为印尼语
- [ ] Mini App `lang="id"`，C 端没有中文硬编码残留
- [ ] 大厅、角色详情、开场白和所有启用卡为印尼语
- [ ] 模型回复为印尼语；发送、流式、重生成、模型/生成偏好可用
- [ ] 新用户赠送、每卡免费额度、签到和无充值星尘策略按配置生效
- [ ] 免费额度耗尽提示与余额不足提示为印尼语，且不引导充值
- [ ] 邀请链接使用 `?startapp=inv_`；注册与聊天轮次奖励到账；首次付费奖励不触发
- [ ] 消息中心公告、客服发信与 CS 回复可用
- [ ] 创作/许愿占位，不产生许愿数据
- [ ] 充值/订单占位，直接 URL 和支付回跳不产生订单
- [ ] 语音所有入口占位，不调用 TTS
- [ ] 聊天、模型切换和语音的余额不足分支均不跳真实充值
- [ ] 印尼服务和数据库未连接中文环境；中文现网抽查未受影响

---

## 5. 本期不做与变更边界

- 真实支付、充值、订单结算、支付 Worker/Cron
- 真实许愿写入、语音合成与音色/供应商适配
- 中文仓库的 i18n、locale/市场开关、运行时中译印
- 中文与印尼共用用户、会话、钱包、角色、配置或数据库 project
- 为未来双市场合一提前重构

不改对话引擎、SSE、计费 RPC 和邀请绑定/发奖的控制流；只在印尼副本中变更入口、文案、内容、环境与配置。

---

## 6. 停止或继续的后续处理

- **停止试水：** 停印尼 Bot、Vercel、Railway，归档印尼仓库和 Supabase project；中文仓库不需要回滚。
- **继续投入：** 新开后续阶段，按优先级恢复支付、许愿或语音的真实链路；届时再评估是否需要收拢两份代码。
